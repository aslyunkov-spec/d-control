# D-Control UI Guidelines

## General

The UI must remain compact, calm and predictable.

The interface should emphasize work, not decoration.

---

# Typography

* Compact font.
* No unnecessary bold text.
* Secondary information uses smaller font size.
* Headings are concise.

---

# Cards

Task cards should display only information needed for quick decisions.

Recommended content:

* Title
* Assignees
* Priority
* Due date
* Comments count
* Files count
* Subtask progress

Avoid unnecessary labels.

---

# Selection

Selected task:

* highlighted by a thin accent bar on the left.

Do not recolor the whole card.

---

# Right Panel

The right panel is permanent.

It is not a modal dialog.

The Kanban board always remains interactive.

---

# Menus

Only one context menu may be open.

Menu closes on:

* outside click
* Escape
* selecting an action
* second click on the same button

---

# Subtasks

Collapsed:

☑ 2/5 ▼

Expanded:

☐ Prepare contract

☑ Send invoice

* New subtask

Rules:

* one subtask level only;
* checkbox changes completion state;
* title opens subtask;
* ▼ expands/collapses;
* list stays expanded until user collapses it.

---

# Spacing

Keep vertical spacing minimal.

Avoid empty space.

---

# Buttons

Small.

Square.

Left aligned.

No oversized controls.

---

# Timeline

Chronological.

Oldest at the top.

Newest at the bottom.

Do not duplicate information already visible elsewhere.

---

# Files

Represent by file-type icons.

Examples:

PDF

DOCX

XLSX

PNG

TXT

Show filename.

Do not overload the Timeline.

---

# Colors

Use color only to convey meaning.

Avoid decorative colors.

Examples:

* selected task
* high priority
* success
* warnings

Backgrounds should remain neutral.

---

# Future Rule

Every UI change should satisfy:

* fewer clicks;
* less visual noise;
* higher information density;
* faster everyday work.
