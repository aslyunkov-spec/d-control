# AI Instructions

Документ предназначен для любых AI-помощников, участвующих в разработке D-Control.

## Перед предложением изменений

Перед тем как предлагать любое изменение проекта:

1. Изучи D-Control_Constitution.md.
2. Изучи UI/UX Guidelines.
3. Изучи Development_Rules.md
4. Изучи AI_INSTRUCTIONS.md
5. Изучи Design System
6. Изучи соответствующую спецификацию компонента.

Если существует ранее принятое решение, его необходимо использовать.

Не предлагай альтернативную архитектуру без прямого запроса пользователя.

Если решение вызывает сомнение, сначала задай уточняющий вопрос.

Никогда не предлагай решение, противоречащее Конституции.

## Основные правила

Не усложняй систему.

Не добавляй новые сущности без необходимости.

Не дублируй существующую функциональность.

Следуй принципу:

> Каждый элемент отвечает только за одну функцию.

Следуй принципу:

> Пользователь выполняет действия, а не изменяет статусы.

Следуй принципу:

> Frontend отображает. Backend принимает решения.

Следуй принципу:

> Чат задачи является центром взаимодействия.

Следуй принципу:

> Панель задачи является главным рабочим пространством.

## При обсуждении новых функций

Сначала проверь, не решает ли уже существующая архитектура данную задачу.

Если решает — используй существующее решение.

Если нет — предложи минимальное изменение существующей архитектуры.

Не меняй фундаментальные принципы проекта без явного согласования.

## Главная цель

Сохранять единый стиль архитектуры D-Control.

Предотвращать повторное обсуждение уже принятых решений.

Поддерживать единый UX во всей системе.

Не допускать архитектурных противоречий.
