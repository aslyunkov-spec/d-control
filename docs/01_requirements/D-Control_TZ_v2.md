# D-Control ТЗ v2

## 1. Board UI

- Отделы отображаются как tabs:
  - Юридический;
  - Бухгалтерия;
  - IT;
  - HR;
  - Руководство.
- Выбор отдела переключает доску.

## 2. Columns

- Колонки — это направления внутри отдела.
- Пример для Юридического отдела:
  - Суды;
  - Письма;
  - Запросы;
  - Согласования.
- Колонки создаются вручную.
- Можно менять порядок.
- Можно добавлять и удалять.
- В будущем колонки поддерживают Drag & Drop карточек.
- Для Drag & Drop использовать React DnD или аналог.

## 3. Sections Inside Each Column

Внутри каждого столбца 4 секции:

- Активные;
- Отложенные;
- Выполненные;
- Архив.

### Активные

- новые;
- в работе;
- возвращены на доработку.

### Отложенные

- задачи с паузой до даты;
- пример: Вернуть 01.08.2026;
- после даты авто-возврат в активные или reminder — уточнить позже.

### Выполненные

- все исполнители завершили свои части;
- задача еще не закрыта;
- статус: `completed_pending_review`.

### Архив

- после подтверждения пользователем с permission `close_task`;
- секция collapsed по умолчанию.

## 4. Subtasks

- Подзадачи нужны.
- Используем вариант mini-tasks:
  - исполнитель;
  - дедлайн;
  - статус;
  - связь с родительской задачей.

## 5. Deadline Reminders

- Настраиваемые напоминания:
  - за 1 час;
  - за 3 часа;
  - за 1 день;
  - за 3 дня;
  - custom.
- Каналы:
  - email;
  - inbox.

## 6. Soft Delete

- Удаление не физическое.
- Использовать:
  - `deleted_at`;
  - `deleted_by`.
- Корзина:
  - хранение 30 дней;
  - restore;
  - permanent delete after 30 days.

## 7. Right Task Panel

Содержит:

### Верхняя часть

- ID задачи;
- название;
- отдел;
- колонка;
- приоритет;
- дедлайн;
- постановщик;
- исполнители;
- наблюдатели;
- статус.

### Timeline

- создание;
- изменение статуса;
- комментарии;
- вложения;
- mentions;
- subtask updates;
- закрытие.

### Файлы

- живут в Timeline;
- клик по файлу открывает preview, если поддерживается.
- поддержка preview:
  - PDF;
  - PNG;
  - JPG;
  - TXT.
- В перспективе:
  - DOCX;
  - XLSX;
  - через OnlyOffice.
## UI Theme / Background

- Рабочая область Kanban должна поддерживать изменяемый фон.

В будущем пользователь должен иметь возможность выбрать:

- однотонный цвет;
- градиент;
- изображение;
- корпоративный фон.

- Колонки Kanban должны быть полупрозрачными и затемнёнными.

Цель:

- фон рабочей области виден;
- задачи остаются читаемыми;
- интерфейс не выглядит тяжёлым.

- Карточки задач должны оставаться контрастными и хорошо читаемыми.
- Карточки не должны быть слишком прозрачными.

В будущем нужно предусмотреть систему тем:

- светлая тема;
- тёмная тема;
- пользовательский фон;
- корпоративная тема.

При реализации использовать CSS-переменные, например:

- `--app-background`;
- `--column-background`;
- `--card-background`;
- `--text-color`;
- `--muted-text-color`.
